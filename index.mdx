> **Integration Options:**
>
> - **Iframe Integration (Recommended)** – fastest to launch, ships the full WizzGift catalog out‑of‑the‑box; some cards and top‑ups are **exclusive to Iframe**. Minimal engineering effort, themeable (light/dark), automatic updates.
> - **API Integration** – full server‑to‑server control over catalog, pricing, ordering, and fulfillment. Requires you to build UI, handle state, and protect keys.

---

## 1) Getting Started

### 1.1 Create an Account

- Sign up on **WizzGift**.
- **No KYC is required** to create and access developer tools for testing.

### 1.2 Verify Your Email (Recommended)

- For account security and to reduce support friction, **verify your email** from the verification link sent to you.

### 1.3 Locate Your Developer Keys

- In your dashboard, go to **Profile → Developer**.
- You will find:
  - **Iframe Integration ID** (also represents your user ID)
  - **API Key** (server‑side secret). **Do not share publicly.**
- Both values are visible on the **Developer** page. Use the copy buttons to avoid transcription errors.

> You will need **both** values regardless of the integration path you choose.

## 2) Iframe Integration (Recommended)

**Why choose Iframe?**

- Instant access to the **entire WizzGift catalog** with built‑in search, categories, and regional availability.
- **Exclusive items** (certain gift cards and phone top‑ups) are only offered through iframe.
- **Less maintenance:** WizzGift keeps catalog, pricing, and UX updated.
- **Themeable:** Choose **light** or **dark** to match your brand.

### 2.1 Embed the Iframe

Add the following HTML where you want the WizzGift storefront to appear. Replace placeholders accordingly.

```
<!-- WizzGift Iframe Embed -->
<div id="wizzgift-container" style="width:100%;max-width:1000px;margin:0 auto;">
  <iframe
    id="wizzgift-iframe"
    title="WizzGift Storefront"
    src="https://app.wizzgift.com/iframe?integration_id=YOUR_IFRAME_INTEGRATION_ID&theme=dark&currency=USD&locale=en-US&success_url=https%3A%2F%2Fyourapp.com%2Fgiftcards%2Fsuccess&cancel_url=https%3A%2F%2Fyourapp.com%2Fgiftcards%2Fcancel"
    style="width:100%;height:900px;border:0;"
    allow="payment *; clipboard-write"
    loading="lazy"
    referrerpolicy="no-referrer"
  ></iframe>
</div>
```

**Query parameters** (append to the `src` URL as needed):

- `integration_id` **(required):** Your Iframe Integration ID from _Profile → Developer_.
- `theme` _(optional)_: `dark` or `light`.
- `currency` _(optional)_: e.g., `USD`, `EUR`, `INR`.
- `locale` _(optional)_: BCP‑47 format, e.g., `en-US`.
- `success_url` _(recommended)_: Encoded URL to redirect after a successful purchase.
- `cancel_url` _(recommended)_: Encoded URL to redirect if a user cancels.
- `user_id` _(optional but recommended)_: Your internal user identifier to reconcile orders.
- `email` _(optional)_: Prefill buyer email to improve delivery.
- `disable_categories` _(optional)_: Comma‑separated category slugs to hide (e.g., `gaming,travel`).

> **Note:** The base iframe URL shown above (`https://app.wizzgift.com/iframe`) is a placeholder. Use the exact base URL from your environment if different.

### 2.2 Handling Completion Events (postMessage)

For an SPA or if you prefer not to redirect, listen for postMessage events from the iframe.

```
<script>
  window.addEventListener("message", (event) => {
    // SECURITY: validate origin
    const allowedOrigin = "https://app.wizzgift.com"; // replace if different
    if (event.origin !== allowedOrigin) return;

    const { type, payload } = event.data || {};

    if (type === "wizzgift.order.completed") {
      // Example payload shape (subject to change):
      // { orderId, amount, currency, sku, codeMasked, userId }
      console.log("Order completed:", payload);
      // Optionally: show success UI, refresh balance, etc.
    }

    if (type === "wizzgift.order.cancelled") {
      console.log("Order cancelled:", payload);
    }
  });
</script>
```

> Even when you use `postMessage`, we recommend enabling **Webhooks** (see §4) on your server for a reliable source of truth.

### 2.3 Theming

Use the `theme` parameter to switch between `light` and `dark`.

- Example: `...&theme=light`
- You can embed the iframe in a responsive container and adjust height with CSS or resize events.

## 3) API Integration

Use the server‑to‑server API if you need full control over UX and flows. **Never expose your API Key in client‑side code.**

### 3.1 Authentication

Send your API key in the `Authorization` header.

```
Authorization: Bearer YOUR_API_KEY
```

### 3.2 Common Base

```
Base URL: https://api.wizzgift.com/v1    # placeholder, confirm your environment
```

### 3.5 Example: Node (Hono on Cloudflare Workers)

```
import { Hono } from 'hono'

const app = new Hono()
const API_BASE = 'https://api.wizzgift.com/v1' // placeholder

app.get('/catalog', async (c) => {
  const res = await fetch(`${API_BASE}/catalog?currency=USD`, {
    headers: { Authorization: `Bearer ${c.env.WIZZGIFT_API_KEY}` },
  })
  return c.json(await res.json(), res.status)
})

app.post('/orders', async (c) => {
  const body = await c.req.json()
  const res = await fetch(`${API_BASE}/orders`, {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${c.env.WIZZGIFT_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(body),
  })
  return c.json(await res.json(), res.status)
})

export default app
```

### 3.6 Example: Next.js (Route Handler)

```
// app/api/wizzgift/catalog/route.ts
import { NextResponse } from 'next/server'

const API_BASE = 'https://api.wizzgift.com/v1' // placeholder

export async function GET() {
  const r = await fetch(`${API_BASE}/catalog`, {
    headers: { Authorization: `Bearer ${process.env.WIZZGIFT_API_KEY}` },
    cache: 'no-store',
  })
  return NextResponse.json(await r.json(), { status: r.status })
}
```

## 4) Webhooks (Server‑Side Events)

Use webhooks to receive **reliable** order lifecycle notifications (delivered, failed, refunded, etc.).

### 4.1 Configure Endpoint

- In **Profile → Developer → Webhooks**, set your public HTTPS endpoint, e.g., `https://api.yourapp.com/webhooks/wizzgift`.
- Choose events you want to receive (e.g., `order.delivered`, `order.failed`).

### 4.2 Example Handlers

#### 4.2.1 Node (Express)

```
import express from 'express'
import crypto from 'crypto'

const app = express()
app.use(express.json({ type: '*/*' }))

app.post('/webhooks/wizzgift', (req, res) => {
  // Optional signature check (if enabled in your environment)
  const signature = req.header('X-Wizzgift-Signature')
  const secret = process.env.WIZZGIFT_WEBHOOK_SECRET
  if (signature && secret) {
    const digest = crypto
      .createHmac('sha256', secret)
      .update(JSON.stringify(req.body))
      .digest('hex')
    if (digest !== signature) return res.status(400).send('Invalid signature')
  }

  const event = req.body
  switch (event.type) {
    case 'order.delivered':
      // mark delivered, persist code if present
      break
    case 'order.failed':
      // refund or notify support
      break
  }
  res.sendStatus(200)
})

app.listen(3000)
```

#### 4.2.2 Hono (Cloudflare Workers)

```
import { Hono } from 'hono'
import { sha256 } from 'hono/utils/crypto' // or use SubtleCrypto directly

const app = new Hono()

app.post('/webhooks/wizzgift', async (c) => {
  const raw = await c.req.text()
  const event = JSON.parse(raw)

  const sig = c.req.header('X-Wizzgift-Signature')
  const secret = c.env.WIZZGIFT_WEBHOOK_SECRET
  if (sig && secret) {
    const hash = await sha256(raw + secret, 'hex')
    if (hash !== sig) return c.text('Invalid signature', 400)
  }

  // handle event.type
  return c.text('ok')
})

export default app
```

## 5) Choosing the Right Integration

| Criterion        | Iframe                                | API                                                         |
| :--------------- | :------------------------------------ | :---------------------------------------------------------- |
| Time‑to‑launch   | **Fastest**                           | Medium/High                                                 |
| Catalog coverage | **Full; includes exclusive items**    | Must fetch & render yourself; some items may be iframe‑only |
| Branding         | Theme (light/dark), container control | Full custom UI                                              |
| Maintenance      | **Low**                               | High (UI, catalog sync, errors)                             |
| Security         | Keys never touch client               | Must keep API key server‑only                               |
| Flexibility      | Medium                                | **Maximum**                                                 |

**Recommendation:** Start with **Iframe** unless you have strong UI/UX requirements or must orchestrate complex server‑side flows.

---

## 6) Security & Compliance

- Treat the **API key** like a password. Store in **server‑side secrets** (environment variables, vaults). Never embed in client apps.
- Use HTTPS everywhere.
- Implement **idempotency** on your side when creating orders (e.g., `external_id`).
- Use **Webhooks** for final state; do not rely solely on client events.
- Log order IDs and your `external_id` for reconciliation.

---

## 7) Errors

Common HTTP codes (representative):

- `400` – validation error (missing fields, invalid amount)
- `401` – invalid or missing API key
- `403` – not allowed for your account/region
- `404` – unknown SKU or order
- `409` – duplicate `external_id`
- `422` – amount or currency not supported for SKU
- `429` – rate limit
- `500` – internal error (retry with backoff)

**Error schema (example)**

```
{
  "error": {
    "code": "invalid_amount",
    "message": "Amount must be one of [10,25,50,100] for this SKU"
  }
}
```

## 8) OpenAPI (for Mintlify Try‑It)

If you have an OpenAPI document, add it under `/openapi/wizzgift.yaml` and reference it from `mint.json` so Mintlify renders **Try‑It**.

`openapi/wizzgift.yaml`**(skeleton):** 

```
openapi: 3.0.3
info:
  title: WizzGift API
  version: 1.0.0
servers:
  - url: https://api.wizzgift.com/v1
paths:
  /catalog:
    get:
      summary: List catalog items
      parameters:
        - in: query
          name: currency
          schema: { type: string }
        - in: query
          name: country
          schema: { type: string }
      responses:
        '200': { description: OK }
  /orders:
    post:
      summary: Create order
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                sku: { type: string }
                amount: { type: number }
                currency: { type: string }
                recipient_email: { type: string }
                external_id: { type: string }
      responses:
        '201': { description: Created }
  /orders/{orderId}:
    get:
      summary: Get order
      parameters:
        - in: path
          name: orderId
          required: true
          schema: { type: string }
      responses:
        '200': { description: OK }
components:
  securitySchemes:
    bearerAuth:
      type: http
      scheme: bearer
      bearerFormat: JWT
security:
  - bearerAuth: []
```

## 9) FAQ

**Do I need KYC to start?** No; creating an account and accessing developer tools does not require KYC.

**Where do I find my keys?** Profile → Developer → _Iframe Integration ID_ and _API Key_.

**Which integration should I use?** Prefer **Iframe** for speed, coverage, and exclusive items. Use **API** for advanced customization.

**Can I theme the UI?** Yes. Use `theme=light|dark` on the iframe.

**How do I test webhooks locally?** Use a tunneling tool (e.g., `cloudflared`, `ngrok`) to expose your local endpoint.
